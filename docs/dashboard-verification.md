# ダッシュボードの実装と確認手順

2026-09-05。作業ブランチは既存の `feature/receipt-form-ui`。カメラフォーム共通化のコミット `056a7fe` を保持したまま、ダッシュボードを追加。利用者の動作確認とマージ・デプロイの承認が完了。反映状況はGitHubのPRおよびProduction Deploymentで管理する。

## 実装した範囲

- 概要のヘッダーから `/dashboard` に移動。概要のカード・タブの構成は維持。
- 対象月の直接指定、前月・翌月、今月、再読み込み。対象月はURLに保持。概要に戻っても概要側の選択月は変更しない。
- 家計支出、前月との差額・増減率、記録上の収支。
- 対象月の日別・週別・累計の利用ペース。累計のみ前月の同日までの線を併記。
- 直近6か月の支出推移と、対象月を切り替える操作。
- カテゴリ別の当月・前月比較。増加額順／利用額順の切り替え。
- カテゴリ明細の店舗・日付・支払者・世帯向け立替・レシート表示、編集・削除、再集計。
- 未分類の支出を内訳に含める。概要の円グラフとその明細にも同じ修正を適用。
- 月次・期間取得をページングし、1,000件を超えても全件取得。画像との関連付けも分割取得。
- カメラの共通フォームは既存実装を利用し、チェックボックスから最初の保存で家庭向け立替になることを回帰テストで確認。

DBマイグレーション・追加環境変数・追加のアプリ依存ライブラリはなし。今回、レシートの下書き保持、入力項目の再配置、店舗検索などのレビュー上の別提案は実装していない。

## 集計と画面の約束

- 家計支出は通常支出＋世帯向け立替。個人向け立替、精算、未登録レシートは除外する。
- 発生日で集計し、現在月は今日まで、過去月は全期間。未来の記録を利用実績として表示しない。
- 現在月の比較は前月同日まで。前月が短い場合は末日まで。過去月のサマリー比較は前月全期間。
- 日別・週別の合計と累計の最終値は対象期間の家計支出と一致する。
- 週は月曜〜日曜。月外の日は含めず、途中週や月端には集計日数と「一部期間」を表示。日数が異なる週に機械的な増減評価を付けない。
- 未来日はグラフ上でnullとし、0円の線を延ばさない。前月に存在しない日も前月線を延ばさない。
- 記録のない経過日は0円。「記録なし」と実際の支出ゼロを自動判別できるとはしない。
- 前月支出0円の場合の増減率は「—」。金額差は表示する。
- 編集や再読み込み中は同じ対象期間の表示状態を保持する。別月・別世帯の読み込み結果を新しい対象期間に混ぜない。日別／週別／累計の表示モードは月を移動しても保持する。
- 別端末の更新は「再読み込み」で取得する。リアルタイム同期や月末予測は今回の範囲外。

## 手元での確認

ルートで `nvm use`、`pnpm --filter web dev` を実行する。既存の `.env.local` を利用する。

1. ログイン後、概要で取引のある月を選択し「ダッシュボード」を開く。家計支出が概要と一致する。
2. 日別・週別・累計を切り替え、確認する日／週を選ぶ。週別の合計と月額、累計の最終値が一致する。
3. 今月に移動し、今日以降に0円の折れ線が延びていないこと、今週の日数表示、前月同日までの比較を確認する。
4. 前月・翌月・月選択を試し、再読み込みしてもURLの月が維持されることを確認する。月端の短い週、記録のない月、未来月も確認する。
5. カテゴリを開き、明細合計が棒グラフの当月額と一致することを確認する。未分類があれば、その明細も開ける。
6. 動作確認用の取引を編集／削除し、家計支出・利用ペース・カテゴリ比較が更新されることを確認する。
7. 「概要に戻る」で元の概要の月を確認する。カメラの支出フォームには家庭向け立替のチェックがあり、最初の保存で登録できる。
8. スマホで日別／週別の切り替え、月の選択、カテゴリ明細、編集フォームを確認する。
